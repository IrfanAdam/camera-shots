## How this is computed

- **Surfaces** come from `design-system/surfaces.json`. A page that links `tokens.css`
  without a surface row fails the build, so a new surface cannot be invisible.
- **Committed HEAD.** Scanned sources are read with `git show HEAD:<path>`, following
  `build-foundations.mjs`: a lane mid-edit on a page cannot drift this file, and it
  describes the commit CI checks out. Commit the change, then regenerate.
- **Quarantine.** `docsOnly: true` on the gallery means its refs are counted but never
  contribute to `productRefCount`; a stylesheet only the gallery loads is treated the same
  way. This is the same rule as `lint-tokens.mjs` T8, so the two gates agree on zero-consumer tokens.
- **Token refs** are `var(--x)` plus quoted reads inside `CT(…)`, `WA(…)` and
  `getPropertyValue(…)` calls. A string read carries `dynamic: true`: the value is resolved
  by a script at runtime (the engine canvas, two gallery probes), not by the cascade alone.
- **Components** are `ds-*` names in `class="…"` (including markup authored inside JS
  template strings), `classList.add/remove/toggle/contains`, `className =` and
  `setAttribute('class', …)`. Anything authored in JS is flagged `dynamic`.
- **Instances are authored occurrences, not DOM nodes.** A template that renders one row per
  group counts once; runtime multiplicity is not guessed. That under-count is visible here.
- **Shared stylesheets** are attributed to every surface that links them, so `productRefCount`
  is reach, not occurrences — it can exceed `refCount`. Per-surface token sets count only what
  the page names plus sheets only that surface loads; shared reach lives in `bySurface`.
- **Blocks** come from the numbered `/* N · … */` sections of `components.css`; a class belongs
  to the first section where it is the subject of a selector, not a member of a shared
  `:is(…)` group. Classes styled only in `base.css` are `structural`; markup-only classes
  are `utility`, and `.ds-icon` is the one utility with no rule of its own.
- **No line numbers and no timestamps** are stored, so ordinary edits do not churn the file.
  `node scripts/build-usage.mjs --lines` prints a file:line drill-down for debugging.
